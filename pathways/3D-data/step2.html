EFI Data-led Research Methods

Data Wrangling

The first product of active and passive data acquisition is normally a point cloud. From the point cloud, different steps are needed to clean and refine the model. Depending on the intended use of the model, you can decide which wrangling steps are required.

Point Cloud

The initial point cloud you are going to have will look different depending on which data wrangling stage you begin at, i.e. “Scanning Data” or “From Photos to 3D”.

If you are working with data obtained through a scanner, you will already have a dense point cloud. A dense point cloud means that by looking at the point cloud you will be able to see the structure of the object in detail. This cloud may or may not contain colour information depending on the instrument you used.

If you are working with data obtained through photogrammetry/SfM, the initial point cloud will be a sparse point cloud. The sparse point cloud is the representation of every single point on the object for which the algorithm was able to accurately make an assumption on its position in space. In a way, this is the truest representation of the surface but may have holes or gaps where elevation data may be missing due to sparse alignment between photos. A dense point cloud contains a much larger number of data points that are densely sampled across the scene. These point clouds capture intricate details and more accurately represent the surfaces of objects and structures in the scene. Because the starting data are photos, the sparse and dense point clouds contain colour information.

Polygon Mesh

A mesh is the standard final product of scanning and photogrammetry and it is a way to represent the surface or boundary of a 3D object or scene. It consists of interconnected vertices, edges, and faces that collectively define the shape and structure of the object. Vertices are points in 3D space, edges connect pairs of vertices, and faces are flat polygons formed by connecting three vertices. The algorithms behind this are more complicated than that, but to picture it you can imagine it as a massive connect-the-dots game starting from the point cloud.

Meshes are used to digitally represent a wide range of objects, from simple geometric shapes to complex organic structures. They play a crucial role in various applications like computer-aided design (CAD), video games, animation, virtual reality, and simulations, enabling the creation, manipulation, and rendering of 3D objects in a digital environment.

The same object can be represented by different levels of precision meshes and often you will need to “decimate” your mesh because these are very heavy objects and different software will have different limits on the number of polygons they will be able to handle. In virtual reality environments, 3D objects are often “pyramidal” objects. This means that the same object will actually be a collection of views of the same object at different levels of decimation. If the object is in the background it will be shown at a certain resolution, and the nearer you get to the object, the more detailed it will be.

Main Mesh extensions

File Extension

Description

OBJ (.obj)

The Wavefront OBJ format is a widely used text-based format that supports both geometry and material information. It is a common choice for exchanging 3D models between different software applications.

STL (.stl)

The STL (STereoLithography) format is often used for 3D printing and rapid prototyping. It represents the geometry of the mesh using triangles and can be either binary or ASCII-encoded.

FBX (.fbx)

Developed by Autodesk, the FBX format is a versatile file format that supports various types of data, including mesh geometry, textures, animations, and more. It is commonly used in the entertainment industry, especially for games and animations.

PLY (.ply)

The Polygon File Format (PLY) is used to store a variety of 3D data, including meshes with vertex coordinates, normals, colours, and other attributes. It is used in both research and industry applications.

Collada (.dae)

The Collada format is an XML-based format designed to facilitate the exchange of 3D content between different software applications.

More on Polygon Meshes

Colour and Texture

Not all the data collected through scanners will have colour information. However, there are certain steps that can be performed on software like Meshlab to reconstruct colour information afterwards.

When the data has colour information, these can be subdivided into two types: colour by vertex and proper textures.

The colour by vertex option is the easier one. Basically, each vertex on the mesh will contain an associated RGB value that will be used similarly to a pixel in 2D images to represent the colour of the object. The quality of a colour by vertex representation is directly connected to how dense the mesh is and it can lead to grainy results.

The texturisation approach will be way less dependent on the number of polygons. To simplify, starting from the 3D model, the software programmes will be able to stitch together the different photos into a “blanket” that will drape perfectly on top of the mesh. Some SfM software, like Metashape, offers really good texturising algorithms that generate incredibly good results even with sub-optimal photos.
